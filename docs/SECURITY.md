# الأمان في متجر Iris

> هذا الملف يشرح **كيف يحمي المتجر نفسه وبيانات الزبائن**، وما الذي يجب على المالك فعله قبل الإطلاق.
> أي تعديل على آلية أمنية يجب أن يرافقه تحديث لهذا الملف واختبار.

## 1) ما الذي نحمي منه؟ (نموذج التهديدات باختصار)

| التهديد                          | مثال                             | الحماية                                                                                              |
| -------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------- |
| تخمين كلمات المرور               | تجربة آلاف كلمات المرور على حساب | قفل مؤقت بعد 8 محاولات خاطئة + حد لكل IP + Argon2id بطيء + Turnstile اختياري                         |
| سرقة جلسة                        | XSS يقرأ الكوكيز                 | كوكيز `HttpOnly` + `Secure` + `SameSite=Lax` + CSP بـ nonce                                          |

| حقن سكربت (XSS)                  | وصف منتج يحوي `<script>`         | تنقية HTML (allow-list) + React يهرّب النصوص + CSP يمنع السكربتات غير الموقّعة                       |

| الاستيلاء على متجر جديد          | شخص يسبقك إلى صفحة الإعداد       | `/setup` يتطلب `SETUP_TOKEN` السري ويُغلق نهائياً بعد إنشاء المالك                                   |
| موظف مخترَق                      | سرقة كلمة مرور موظف              | تحقق بخطوتين إلزامي، صلاحيات محددة لكل دور، جلسات الإدارة تنتهي كل 24 ساعة، سجل تدقيق                |
| طلبات وهمية (الدفع عند الاستلام) | روبوت يُغرق المتجر بطلبات مزيفة  | حد للطلبات لكل IP ولكل رقم هاتف + Turnstile للزوار (اختياري)                                         |
| البيع الزائد (Overselling)       | زبونان يشتريان آخر قطعة معاً     | قفل صفوف المخزون داخل معاملة الطلب، والقاعدة تمنع المخزون السالب                                     |

### الأدوار والصلاحيات (`src/server/auth/permissions.ts`)

| الدور                           | الصلاحيات                               |
| ------------------------------- | --------------------------------------- |
| `owner` المالك                  | كل شيء، بما فيها إدارة الموظفين         |
| `admin` مدير                    | كل شيء عدا إدارة الموظفين               |
| `catalog_manager` مدير المنتجات | المنتجات، المخزون، المحتوى، عرض الطلبات |
| `order_manager` مدير الطلبات    | الطلبات والزبائن (عرض المنتجات فقط)     |
| `customer` زبون                 | لا وصول للإدارة                         |

> الصلاحيات تُفحص **على الخادم في كل عملية** (`assertStaff(permission)`)، وليس بإخفاء الأزرار فقط.

### إدارة الأشخاص من لوحة التحكم

- **إدارة الموظفين للمالك فقط** (`staff:manage`). لا أحد يغيّر صلاحيته بنفسه، ولا تُغيَّر صلاحية المالك أو تُمنح لغيره من اللوحة.
- **أي تغيير في الصلاحية يحذف كل جلسات الشخص**: الزبون المُرقّى لا يحتفظ بجلسة دخلها برمز البريد، بل يدخل من جديد
  بكلمة المرور ثم يُجبر على تفعيل التحقق بخطوتين. الجلسات لا تُخزَّن في الكوكيز (`cookieCache` متوقف)، فالأثر فوري.
- **إيقاف زبون** (`banned`) يحذف جلساته ويمنع إنشاء جلسة جديدة (`ACCOUNT_SUSPENDED`).
- الإعدادات المرتبطة بالبيانات (الدولة، العملة، رمز الهاتف، التوقيت) **مقفلة** بعد الإعداد ولا تُقبل من اللوحة.
- روابط أزرار الصفحة الرئيسية تقبل `/مسار` داخلياً أو `http(s)://` فقط (لا `javascript:`)، والصفحات تُنظَّف كالأوصاف.
- رفع الصور عبر `/api/admin/media`: نفس المصدر (`Origin` و`Sec-Fetch-Site`)، صلاحية `products:write` أو
  `content:write`، 200 رفعة/ساعة لكل موظف، ثم فحص التوقيع وإعادة الترميز كما في الأعلى.

## 4) المتصفح والشبكة

- **CSP صارم** بـ nonce جديد لكل طلب و`strict-dynamic` (`src/proxy.ts`)، و`frame-ancestors 'none'`، و`object-src 'none'`.
- ترويسات: `HSTS` (سنتان + preload)، `X-Content-Type-Options: nosniff`، `X-Frame-Options: DENY`،
  `Referrer-Policy`، `Permissions-Policy`، `COOP`، وإخفاء `X-Powered-By`.
- واجهة Better Auth المفتوحة للمتصفح **محصورة** في روابط العودة من Google وفحص الصحة فقط
  (`src/app/api/auth/[...all]/route.ts`)؛ كل العمليات الأخرى عبر Server Actions بحماياتها.
- عنوان IP الحقيقي يُستخرج وفق عدد البروكسيات الموثوقة (`TRUSTED_PROXY_COUNT`) فلا يمكن تزويره.
  في النشر بـ Docker:
  - يعمل Caddy على شبكة الخادم مباشرة، فيرى عنوان كل زائر (IPv4 وIPv6).
  - يستبدل Caddy أي `X-Forwarded-For` قادم من الزائر، ولا يثق إلا بعناوين Cloudflare إن فُعّلت (`CADDY_TRUSTED_PROXIES`).
  - تم التحقق من ذلك بتشغيل الحزمة كاملة وإرسال ترويسات مزوّرة.
  - المتجر نفسه لا يستمع إلا على `127.0.0.1`.
- روابط العودة بعد الدخول تقبل مسارات داخلية فقط (منع Open Redirect).

## 5) البيانات

- رموز التحقق (OTP) مخزّنة مشفّرة (hash)، ولا تُكتب في السجلات أبداً.
- السجلات (pino) تحجب تلقائياً: كلمات المرور، الرموز، الكوكيز، ترويسات التفويض.
- **سجل التدقيق** (`audit_logs`) لكل عملية إدارية وأمنية، **محمي من التعديل والحذف** بـ Trigger في القاعدة.
- مفاتيح تحديد المعدل التي تحوي بريداً تُخزَّن كـ hash.
- الصور: حذف بيانات EXIF/GPS عند الرفع.
- ملفات المنتجات (CSV):
  - التنزيل والاستيراد بصلاحية `products:write` فقط، لأن الملف يحوي التكلفة، وكلاهما في سجل التدقيق.
  - الخلايا التي تبدأ بـ `=` `+` `-` `@` تُصدَّر مسبوقة بـ `'` حتى لا يشغّلها Excel كمعادلات (CSV injection).
  - الاستيراد يُفحص كاملاً ثم يُطبَّق في معاملة واحدة، بحدود للحجم وعدد الأسطر والمحاولات.
- **السلة:** المتصفح يحمل رمزاً عشوائياً فقط (كوكي `HttpOnly`، وبادئة `__Host-` على HTTPS)، والقاعدة تحفظ
  الـ hash. عند تسجيل الدخول تُدمج سلة الزائر في الحساب ويُغيَّر رمزها، فلا يصل إليها أحد بعد الخروج.
- **روابط الطلبات:** سرّ مشتق بـ HMAC من مفتاح الطلب (يُخزَّن hash فقط)، والصفحة تُرسل `Referrer-Policy: no-referrer`
  ولا تُفهرس. الرابط يصل للزبون في البريد؛ احمِ سجلات الخادم (Access logs) لأنها قد تحوي الروابط.
- **إتمام الطلب:** السعر والإجمالي يُعاد حسابهما على الخادم، وإن اختلفا عمّا رآه الزبون يُرفض الطلب ويُعرض الإجمالي الجديد
  (لا خصم صامت)، وتكرار الضغط على "تأكيد الطلب" يعيد الطلب نفسه (Idempotency).
- **الإشعارات:** تُكتب في `outbox_messages` داخل معاملة الطلب ثم تُرسل مع إعادة المحاولة (لا تضيع ولا تُرسل لطلب ملغى).
- **حزم المتصفح:** مكتبة التحقق (zod) لا تُرسل للمتصفح، واختبار E2E يفشل عند أي مخالفة CSP في الصفحات الرئيسية.

## 6) ✅ قائمة المالك قبل الإطلاق

- [ ] الموقع يعمل على **HTTPS** فقط (`APP_URL=https://...`).
- [ ] `AUTH_SECRET` عشوائي طويل (`openssl rand -base64 48`) ولا يُشارك مع أحد.
- [ ] بعد إنشاء حساب المالك: **احذف `SETUP_TOKEN`** من الإعدادات.
- [ ] فعّل التحقق بخطوتين لكل حساب إداري (إلزامي تلقائياً).
- [ ] اضبط مزود البريد (`EMAIL_DRIVER=smtp` أو `resend`) — بدونه لا تصل رموز التحقق.
- [ ] (موصى به) فعّل Cloudflare Turnstile ضد الروبوتات، و`PWNED_PASSWORDS_CHECK=true`.
- [ ] نسخ احتياطي يومي لقاعدة البيانات خارج الخادم + تجربة الاستعادة (انظر `DATABASE.md`).
- [ ] حدّث الحزم دورياً (Dependabot مفعّل) وراقب `pnpm audit`.
- [ ] امنح كل موظف **أقل دور يكفيه**، وأزل حسابات الموظفين المغادرين فوراً.

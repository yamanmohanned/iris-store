# ملخص المرحلة 1 — الأساس (Foundation)

**الحالة:** ✅ مكتملة · **الفرع:** `claude/nifty-turing-csz4ep`

## ما تم إنجازه

### 1) هيكل المشروع والأدوات

- Next.js 16.3 (App Router + Turbopack) مع React 19.3 و TypeScript 5.9 بوضع **strict** كامل
  (`noUncheckedIndexedAccess` وغيرها).
- pnpm كمدير حزم مع ملف قفل (`pnpm-lock.yaml`) — نسخ مثبتة بدقة لكل الحزم.
- ESLint (إعدادات Next الرسمية + TypeScript) مع **قاعدة خاصة تمنع أصناف الاتجاه الفيزيائي**
  (`ml-*`, `left-*`, `text-left` ...) لضمان عمل التصميم بالعربية (RTL). Prettier مع ترتيب أصناف Tailwind.

### 2) اللغات واتجاه الصفحة

- next-intl: **العربية افتراضية على `/`** والإنجليزية على `/en`. اتجاه الصفحة (`dir`) ولغتها (`lang`)
  يتغيران تلقائياً. لا تخمين للغة من المتصفح ولا كوكيز للغة (الرابط هو المرجع).
- ملفات الترجمة: `messages/ar.json` و `messages/en.json` (مع تحقق من الأنواع — أي مفتاح ناقص يظهر كخطأ).

### 3) الأمان الأساسي

- **CSP صارم بـ nonce جديد لكل طلب** (`src/proxy.ts` + `src/server/security/csp.ts`): لا يُنفَّذ أي سكربت
  غير موقّع → حماية قوية من XSS. منع التضمين في إطارات (Clickjacking)، `object-src 'none'`.
- ترويسات أمان على كل الردود: HSTS (في الإنتاج)، `nosniff`، `X-Frame-Options: DENY`، `Referrer-Policy`،
  `Permissions-Policy`، `COOP`، وإخفاء `X-Powered-By`.
- نقطة استقبال تقارير مخالفات CSP: `/api/csp-report` (محدودة المعدل، للمراقبة).
- استخراج IP الزبون بشكل آمن خلف البروكسي (`client-ip.ts`) — لا يمكن تزويره عبر ترويسة X-Forwarded-For.
- التحقق من متغيرات البيئة عند التشغيل (`src/server/env.ts`) برسائل واضحة، مع قواعد مثل: `AUTH_SECRET`
  ≥ 32 حرفاً، `https` إجباري في الإنتاج.
- سجلات (pino) تحجب تلقائياً كلمات المرور والرموز والكوكيز.

### 4) نظام التصميم (قابل للتعديل بعد تحليل Stitch)

- Tailwind CSS 4 مع **متغيرات تصميم دلالية** (`src/app/globals.css`): لون الهوية `--primary` واحد تُشتق منه
  بقية الدرجات تلقائياً — سيتمكن المالك من تغييره من لوحة التحكم.
- خط **Readex Pro** (عربي + لاتيني، متغير الأوزان) مستضاف ذاتياً: ~55KB فقط لكل الأوزان، ويُحمَّل مسبقاً.
- مكونات أساسية: `Button`, `Input`, `Textarea`, `NativeSelect` (أفضل تجربة على الهاتف), `Field`,
  `Sheet` (درج سفلي/جانبي للهاتف), `Dialog`, `Checkbox`, `Switch`, `Badge`, `Card`, `Alert`, `Skeleton`, `Toaster`.
- مراعاة الهاتف: حجم خط الحقول 16px (يمنع التكبير التلقائي في iPhone)، مساحات آمنة (notch)، احترام
  "تقليل الحركة".

### 5) قاعدة البيانات المحلية والاختبارات و CI

- `pnpm db:local start`: تشغيل PostgreSQL محلياً **بدون Docker** (قاعدتان: `iris` و `iris_test`).
- `docker-compose.yml` بديل (PostgreSQL + Mailpit لاستعراض الرسائل).
- Vitest (مشروعان: وحدات + تكامل) — **9 اختبارات وحدات ناجحة**.
- Playwright على مقاس **الهاتف (Pixel 7) والحاسوب** — **10 اختبارات E2E ناجحة** (اللغة، الاتجاه،
  ترويسات الأمان، صفحة 404، لا أخطاء CSP في المتصفح).
- GitHub Actions: lint → الأنواع → الاختبارات → تدقيق الحزم → البناء → E2E. و Dependabot للتحديثات.

## الملفات الأهم

| الملف                 | الوظيفة                       |
| --------------------- | ----------------------------- |
| `src/proxy.ts`        | توجيه اللغة + CSP لكل طلب     |
| `src/server/env.ts`   | التحقق من الإعدادات           |
| `src/app/globals.css` | متغيرات التصميم               |
| `src/components/ui/*` | المكونات الأساسية             |
| `scripts/dev-db.sh`   | قاعدة بيانات محلية            |
| `.env.example`        | كل الإعدادات الممكنة مع الشرح |

## كيف تتحقق

```bash
pnpm check            # lint + types + tests
pnpm build && PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm test:e2e
```

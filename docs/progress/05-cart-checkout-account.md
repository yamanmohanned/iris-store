# ملخص المرحلة 5 — السلة والدفع والطلبات وحساب الزبون

**الحالة:** ✅ مكتملة · **الفرع:** `claude/nifty-turing-csz4ep` · تفاصيل الأمان في [`docs/SECURITY.md`](../SECURITY.md)

## ما تم إنجازه

### 1) السلة (`/cart`)

- السلة محفوظة **في قاعدة البيانات** وتبقى 60 يوماً؛ المتصفح يحمل رمزاً عشوائياً فقط (والقاعدة تحفظ الـ hash).
- **الزائر يتسوّق بلا حساب**، وعند تسجيل الدخول أو إنشاء حساب تنتقل سلته إلى حسابه تلقائياً (تُدمج مع سلته السابقة إن وجدت).
- الأسعار والتوفر **حيّة** في كل عرض: إن نفد منتج أو قلّ مخزونه يظهر تنبيه مع زر "تعديل الكمية إلى المتوفر".
- تعديل الكمية والحذف فوراً، كود الخصم مع سبب واضح إن لم يعمل (منتهي، مستخدم سابقاً، يحتاج حداً أدنى…)،
  شريط "أضف X لتحصل على توصيل مجاني"، والإجمالي مثبّت أسفل شاشة الهاتف مع زر "إتمام الطلب".
- زر "أضف إلى السلة" في صفحة المنتج يعمل الآن، مع إشعار فيه "عرض السلة"، وعدّاد السلة في الهيدر والشريط السفلي.

### 2) إتمام الطلب (`/checkout`) — صفحة واحدة مصممة للهاتف

| القسم     | التفاصيل                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| ① التواصل | الاسم، الهاتف (يقبل كل الصيغ: `0770…` و`+964…` والأرقام العربية)، البريد (اختياري أو إلزامي حسب الإعداد)    |
| ② العنوان | المحافظة (مع رسوم التوصيل ومدته)، المدينة، المنطقة، **أقرب نقطة دالة**، الشارع؛ العناوين المحفوظة للمسجّل   |
| ③ الدفع   | الدفع عند الاستلام (يُخفى للمحافظات غير المدعومة) أو التحويل البنكي مع تعليماته بعد الطلب                   |
| ④ ملاحظات | اختيارية (يمكن إيقافها من الإعدادات)                                                                        |
| الملخص    | المنتجات، الخصم، التوصيل يُحسب **فوراً** عند اختيار المحافظة، الإجمالي، وزر "تأكيد الطلب" مثبّت أسفل الشاشة |

- الشراء **كزائر** متاح (يمكن إلزام الحساب من الإعدادات)، والمسجّل يجد اسمه وبريده وعنوانه جاهزة.
- أخطاء واضحة بجانب كل حقل، والتركيز ينتقل لأول حقل يحتاج تصحيحاً.

### 3) إنشاء الطلب — آمن ودقيق (`src/server/services/orders.ts`)

كل شيء يحدث في **معاملة واحدة**: إما أن ينجح كاملاً أو لا يحدث شيء.

- **لا بيع زائد أبداً:** تُقفل صفوف المخزون أثناء الطلب (مختبَر بزبونين يشتريان آخر قطعة في اللحظة نفسها).
- **لا مفاجآت في السعر:** الإجمالي يُعاد حسابه على الخادم، وإن تغيّر عمّا رآه الزبون يُرفض الطلب ويُعرض الإجمالي الجديد.
- **لا طلبات مكررة:** الضغط مرتين على "تأكيد الطلب" يعيد الطلب نفسه.
- **الكوبونات:** حدود الاستخدام الكلية و"مرة لكل زبون" تُحسب بالحساب **وبرقم الهاتف** (بأي صيغة كُتب).
- خصم المخزون مع سجل حركة لكل قطعة، تحديث "الأكثر مبيعاً"، إخفاء المنتج النافد من "المتوفر"، تفريغ السلة،
  وحفظ العنوان في حساب الزبون (إن طلب ذلك).
- **مكافحة الطلبات الوهمية** (مشكلة شائعة في متاجر الدفع عند الاستلام): حد لكل IP ولكل رقم هاتف + Turnstile للزوار.

### 4) بعد الطلب

- **صفحة الطلب** `/order/[رابط سري]`: رسالة "شكراً لك! تم استلام طلبك"، رقم الطلب، شريط مراحل
  (تم الاستلام ← التأكيد ← التجهيز ← في الطريق ← التوصيل)، المنتجات والمبالغ، العنوان، تعليمات التحويل البنكي،
  زر نسخ الرابط، والسؤال عبر واتساب. الرابط سرّي وغير قابل للتخمين ولا يُفهرس.
- **تتبّع الطلب** `/track`: برقم الطلب + رقم الهاتف.
- **البريد:** تأكيد للزبون (مع رابط الطلب)، وتنبيه "طلب جديد" للمالك، وتنبيه "مخزون منخفض".
  الرسائل تمر عبر "صندوق صادر" بإعادة محاولة تلقائية (`src/server/services/outbox.ts`).

### 5) حساب الزبون (`/account`)

| الصفحة               | المحتوى                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------- |
| `/account`           | ترحيب، آخر طلب بحالته، وروابط: طلباتي، عناويني، المفضلة، الأمان (ولوحة التحكم للموظفين) |
| `/account/orders`    | كل الطلبات بالحالة والتاريخ والمبلغ، وتفاصيل كل طلب                                     |
| `/account/addresses` | إضافة/تعديل/حذف (بلمستين للتأكيد)، عنوان افتراضي واحد، حتى 10 عناوين                    |
| `/account/wishlist`  | المنتجات المحفوظة (زر القلب ♡ في صفحة المنتج؛ الزائر يُطلب منه تسجيل الدخول)            |

### 6) تحسينات أخرى

- **أداء:** مكتبة التحقق (zod) كانت تُرسل للمتصفح في صفحات الأقسام والبحث (~50KB) — أُزيلت، ومعها مخالفة CSP كانت تحدث في الخلفية.
- اختبار جديد يفشل عند أي مخالفة CSP في الصفحات الرئيسية.
- مسافات أوضح بين كلمات العناوين العربية بخط Reem Kufi.

## الاختبارات

- **115 اختبار وحدات وتكامل** (جديد: 12 للتسعير والهواتف، 8 للسلة والكوبونات بما فيها التزامن، 10 للطلبات:
  الإجماليات، البيع الزائد المتزامن، التكرار، تغيّر السعر، حد الكوبون بالهاتف، التحقق من المدخلات، التتبّع، البريد؛
  4 للعناوين والمفضلة).
- **42 اختبار متصفح ناجح** على الهاتف والحاسوب (+2 متخطّاة عمداً)، جديد منها: شراء كامل كزائر مع البريد والتتبّع،
  انتقال سلة الزائر إلى حسابه + الطلب بحساب + دفتر العناوين، المفضلة، ومنع مخالفات CSP.

## ملاحظات للمالك

- عدّل **رسوم التوصيل ومدته** لكل محافظة، وفعّل/عطّل الدفع عند الاستلام لكل محافظة (من لوحة التحكم — المرحلة 6).
- لتفعيل **التحويل البنكي** اكتب تعليماته (رقم الحساب/المحفظة) في إعدادات الدفع.
- أضف بريدك في "بريد الإشعارات" ليصلك تنبيه كل طلب جديد.
- الكود التجريبي `WELCOME10`: خصم 10% لأول طلب بحد أدنى 50,000 د.ع.

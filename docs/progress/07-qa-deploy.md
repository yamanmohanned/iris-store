# ملخص المرحلة 7 — الجودة والنشر ودليل المالك

**الحالة:** ✅ مكتملة · **الفرع:** `claude/nifty-turing-csz4ep` · تفاصيل الأمان في [`docs/SECURITY.md`](../SECURITY.md)

## ما تم إنجازه

### 1) المهام الدورية (`/api/cron/*`)

| المهمة    | التوقيت    | ما تفعله                                                                                                                      |
| --------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `outbox`  | كل دقيقة   | ترسل الرسائل التي تأخرت أو تعثّر إرسالها، حتى 6 محاولات، ضمن مهلة 20 ثانية لكل استدعاء                                        |
| `cleanup` | مرة يومياً | تحذف السلال والجلسات المنتهية، ورموز التحقق القديمة، وعدّادات الحماية المنتهية، والرسائل المرسلة بعد 30 يوماً والفاشلة بعد 90 |

- المسار محمي بـ `CRON_SECRET` في ترويسة `Authorization` (مقارنة ثابتة الزمن). أي طلب بدونه يُرفض بـ 401.
- آمنة للتشغيل المتوازي، لأن كل رسالة تُحجز بـ `SKIP LOCKED`، فلا تُرسل رسالة مرتين.
- الملفات: `src/server/services/maintenance.ts` و`src/app/api/cron/[job]/route.ts`.

### 2) التشغيل على خادم (Docker)

| الملف                     | الدور                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `Dockerfile`              | صورة إنتاج بثلاث مراحل: pnpm بالإصدار المثبّت، خادم Next.js المستقل، وأداة تحديث قاعدة البيانات مجمّعة بـ esbuild. تعمل بمستخدم بلا صلاحيات |
| `docker-compose.prod.yml` | PostgreSQL، والمتجر (على `127.0.0.1` فقط)، وCaddy، والمهام الدورية، والنسخ الاحتياطي                                                        |
| `Caddyfile`               | شهادة HTTPS تلقائية مع HTTP/2 وHTTP/3، وضغط الاستجابات                                                                                      |
| `scripts/docker/*`        | بدء التشغيل (تحديث القاعدة ثم الخادم)، والمهام الدورية، والنسخ الاحتياطي                                                                    |
| `.env.production.example` | كل الإعدادات مع أمر توليد كل سر                                                                                                             |
| `docs/DEPLOYMENT.md`      | دليل النشر خطوة بخطوة بالعربية                                                                                                              |

- **تحديث قاعدة البيانات تلقائي** عند كل تشغيل.
- **إعداد ناقص يوقف الخادم فوراً برسالة واضحة**، مثل `AUTH_SECRET` غير موجود. لا يبدأ المتجر ثم يفشل مع كل طلب.
- **`/api/health`** يفحص الاتصال بقاعدة البيانات، ويستخدمه Docker ومواقع مراقبة التوقف مثل UptimeRobot.
- **عنوان الزائر الحقيقي:** يعمل Caddy على شبكة الخادم مباشرة، فيرى عنوان كل زائر (IPv4 وIPv6) وتعمل حدود الحماية لكل زائر على حدة.
  - يتجاهل Caddy أي `X-Forwarded-For` يرسله الزائر.
  - خلف Cloudflare لا يثق Caddy إلا بعناوين Cloudflare.
- **النسخ الاحتياطي:**
  - قاعدة البيانات يومياً، والصور أسبوعياً، مع حذف النسخ الأقدم من المدة المحددة.
  - الدليل يشرح الاستعادة، ونسخ المجلد خارج الخادم.

#### كيف تم التحقق

- بُنيت الصورة وشُغّلت مع PostgreSQL حقيقية. نجحت كل هذه الخطوات بالمتصفح:
  - تحديث القاعدة.
  - إنشاء المالك.
  - تفعيل التحقق بخطوتين.
  - رفع صورة منتج (sharp ومجلد الصور).
  - ظهور المنتج في المتجر.
- شُغّلت الحزمة كاملة بـ `docker compose`:
  - HTTPS عبر Caddy، وتحويل HTTP إلى HTTPS.
  - تجاهل ترويسة IP مزوّرة.
  - وضع Cloudflare: يُسجَّل عنوان الزائر الحقيقي ويُتجاهل العنوان المزوّر.
- أُنشئت نسخة احتياطية واستُعيدت في قاعدة جديدة، وعملت المهام الدورية، ورُفض السر الخاطئ.

#### للمطوّر: بناء الصورة داخل حاويات Claude السحابية

هذه الأوامر للاختبار هنا فقط، فخادم المالك لا يحتاجها:

- Docker Hub يرفض بعد عدد قليل من التنزيلات (429)، لذلك تُستخدم مرآة Google.
- الشبكة تمر بوكيل له شهادة خاصة، تُضاف إلى نسخة محلية من Dockerfile.

```bash
S=<مجلد مؤقت>; mkdir -p $S/ccr && cp /root/.ccr/ca-bundle.crt $S/ccr/
awk '{print} /^FROM \$\{NODE_IMAGE\} AS base$/{print "COPY --from=ccr ca-bundle.crt /usr/local/share/proxy-ca.crt"; print "ENV NODE_EXTRA_CA_CERTS=/usr/local/share/proxy-ca.crt"}' Dockerfile > $S/Dockerfile.local
docker build --network host -f $S/Dockerfile.local --build-context ccr=$S/ccr \
  --build-arg NODE_IMAGE=mirror.gcr.io/library/node:22-bookworm-slim \
  --build-arg HTTPS_PROXY=$HTTPS_PROXY --build-arg HTTP_PROXY=$HTTPS_PROXY -t iris-store:test .
```

لتشغيل `docker-compose.prod.yml` هنا:

1. أعطِ الصور أسماءها المعتادة: `docker tag mirror.gcr.io/library/postgres:16-alpine postgres:16-alpine`، وكذلك Caddy وcurl، و`iris-store:test` باسم `iris-store:latest`.
2. شغّل بـ `--no-build`، مع `DOMAIN=localhost` و`APP_URL=https://localhost`.

### 3) فحص إمكانية الوصول (WCAG 2.2 AA)

اختبار آلي جديد (`tests/e2e/a11y.spec.ts`) يفحص **34 صفحة** بأداة axe على الهاتف والحاسوب:

- **المتجر:** الرئيسية، الأقسام، قائمة قسم، المنتج، السلة، إتمام الطلب، البحث، التتبع، صفحة ثابتة، التواصل، والنسخة الإنجليزية.
- **الدخول والطلب:** الدخول، التسجيل، استعادة كلمة المرور، وتأكيد الطلب.
- **حساب الزبون:** خمس صفحات.
- **لوحة التحكم:** 14 صفحة.

النتيجة الآن: **صفر مخالفات** بكل درجات الخطورة. الاختبار يفشل إن ظهرت مخالفة جدية مستقبلاً.

ما تم إصلاحه:

| المشكلة                                          | الإصلاح                                                                                                                               |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| لون نص التحذير على خلفيته 4.48:1 (الحد 4.5:1)    | لون أغمق قليلاً `#8f5d10`: ‏5.09:1 على خلفيته و5.61:1 على الأبيض                                                                      |
| أعمدة مخطط المبيعات أصغر من 24px للمس على الهاتف | المخطط كله هدف واحد: لمس أو سحب أو تمرير المؤشر يُظهر اليوم، والأسهم تنقل بين الأيام. أصبح المخطط محطة واحدة عند التنقل بـ Tab بدل 14 |
| روابط سجل التدقيق تتميز باللون فقط               | خط سفلي دائم                                                                                                                          |
| ترتيب العناوين في قوائم المنتجات (h1 ثم h3)      | بطاقات المنتجات تحت عنوان الصفحة مباشرة صارت h2                                                                                       |

### 4) الأداء على الهاتف (Lighthouse)

الإعداد:

- محاكاة هاتف متوسط على شبكة 4G بطيئة، مع إبطاء المعالج 4 مرات.
- بيانات المتجر التجريبي، على نسخة الإنتاج.

| الصفحة        | الأداء | إمكانية الوصول | أفضل الممارسات | SEO  |
| ------------- | ------ | -------------- | -------------- | ---- |
| الرئيسية      | 83–88  | 100            | 100            | 100  |
| قائمة قسم     | 87–93  | 100            | 100            | 100  |
| صفحة منتج     | 89–90  | 100            | 100            | 100  |
| السلة         | 91–97  | 100            | 100            | 63\* |
| الدخول        | 94     | 100            | 100            | 63\* |
| الرئيسية (EN) | 85–93  | 100            | 100            | 100  |

\* السلة والدخول والبحث مستبعدة من محركات البحث عمداً (`noindex`)، ولهذا تنخفض درجة SEO فيها.

- **التحميل الفعلي** (بلا محاكاة) يرسم الصورة الرئيسية مع أول ظهور للصفحة خلال 0.2–0.34 ثانية، ولا تنتظر أي JavaScript.
- الاهتزاز البصري (CLS) شبه معدوم: 0–0.003.
- **تحسين:** صور الصف الأول في قوائم المنتجات تُحمَّل فوراً، والصورتان الأوليان بأولوية عالية. ارتفع أداء قائمة القسم من 86 إلى 87–93.
- معظم JavaScript هو React وNext.js نفسيهما (نحو 115 كيلوبايت مضغوطة). كود المتجر صغير.

### 5) دليل المالك

[`docs/OWNER-GUIDE.md`](../OWNER-GUIDE.md) يشرح لوحة التحكم بلا مصطلحات تقنية:

- الدخول والتحقق بخطوتين، وترتيب مقترح لليوم الأول.
- رحلة الطلب: ماذا تعني كل حالة وماذا تفعل.
- المنتجات والمخزون، والأقسام، وواجهة المتجر، والصفحات، والتوصيل، والكوبونات.
- الزبائن، والموظفون والصلاحيات، والإعدادات، وأرقام لوحة الرئيسية، وسجل التدقيق.
- الرسائل التي يرسلها المتجر ومتى، وعادات الأمان.
- أسئلة شائعة، وما ليس متاحاً بعد.
